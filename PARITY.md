# Parity with the Mac app

This is the Windows port of [Term Organize](https://github.com/AlexmChadwick/Northeastern-Term-Organize) (SwiftUI). Logic is in `src/TermOrganize.Core`. The shell is `src/TermOrganize.App` (WinUI 3, Mica, light and dark). Each row was checked against the Swift sources and the C# that is in this tree.

The core library was built and tested on Linux (.NET 9): `dotnet test` passed 299 tests, 0 failed, including the live Banner term-list smoke test. `dotnet build TermOrganize.sln` on Linux leaves the WinUI project as an empty stub (`EnableDefaultCompileItems` is false). `dotnet build src/TermOrganize.App/TermOrganize.App.csproj -c Release -p:EnableWindowsTargeting=true -p:Platform=x64 -p:TreatWarningsAsErrors=true` compiles every App `.cs` file with csc against the Windows App SDK 1.8 reference assemblies (`Microsoft.WinUI`, `Microsoft.Windows.SDK.NET`). That host cannot run the markup compiler or `makepri.exe`, so the Linux check skips both and supplies `InitializeComponent` plus the `x:Name` fields from `NonWindowsXamlStubs.cs`. `.github/workflows/windows.yml` runs on `windows-latest`. The `test` job runs the core suite. The `package` job builds the signed MSIX and the unpackaged zip on its own. A windows-latest run passed all 299 core tests and compiled the WinUI project. MakeAppx rejected an earlier package because `uap3:AppExtension` needs `PublicFolder` when `TargetDeviceFamily` `MinVersion` is 10.0.18307.0 or earlier. The manifest and `TargetPlatformMinVersion` are both 10.0.19041.0, so that attribute is not required. The next MakeAppx run rejected `EntryPoint="Microsoft.Windows.ApplicationModel.Background.UniversalBGTask.Task"` until the package declared `windows.activatableClass.inProcessServer` for that class. The manifest now has that package extension, and the build copies `Microsoft.Windows.ApplicationModel.Background.UniversalBGTask.dll` to the package root. `Square71x71Logo` no longer points at the 44×44 image. `makepri.exe` and `makeappx.exe` still do not run on Linux. The Windows package job publishes the unpackaged app self-contained (`WindowsAppSDKSelfContained=true`, framework bootstrap off, `resources.pri` included), waits for `--screenshot-sweep` to exit, and uploads light and dark shots of each page at 1440×900 and 800×900 as the `ui-sweep` artifact even when the capture fails. Startup exceptions are written to `error.txt`. Narrow windows collapse the navigation pane, wrap toolbars, and keep both sides of a split inside the window. The title bar is 48px so the caption buttons are not covered.

## Tests

Swift tests under `NEUClassSearchTests` were ported to xUnit in `tests/TermOrganize.Core.Tests`: models, search, Banner parsers, the catalog, schedules (generator, preferences, blockers, brute force), degree-plan text and PDF, the degree audit and NUpath fixtures, random audit matching, attribute lookup, watchlist, rooms, professors, cloud-sync merge, the preference parser, and the term, catalog-cache, calendar-draft, offering-history, and seat-check helpers. On Linux, `dotnet test` of that project passed (299 tests, 0 failed).

## Not the same

- Widgets Board is packaged only and was not run. Unpackaged installs use the tray flyout. There is no EventKit and no signed-in iCloud account. Windows Calendar is the Appointments API, with an .ics fallback.
- Catalog files this port saves are gzip. It still opens the Mac `.catalog` format.
- The shell C# was compiled on Linux against the Windows App SDK reference assemblies, with warnings treated as errors. The markup compiler, print dialog, widget provider, background COM server, Task Scheduler, toasts, and the Appointments API were not run on Windows in this environment.
